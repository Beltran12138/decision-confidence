Three numbers per board, and why they are deliberately simple

A leaderboard ranks entries by what they made. The question we add is how much of that ranking could be luck. Everything here can be recomputed from the board's own public data with the script in the repository; nothing depends on a model of ours.

1 · From an equity curve to t

For each entry we take the published equity history, keep the last value of each day, and compute daily returns.

Sharpe (annualised) = mean(daily return) / sd(daily return) × √(days per year) t = Sharpe × √(years of data)

Crypto boards trade every day, so we annualise with 365; boards on equity calendars use 252. The edition JSON records which. A single, pre-chosen strategy needs t ≥ 2 to be distinguishable from zero (one-sided, about 2.3%).

This is the i.i.d. approximation (Lo, 2002). Fat tails and autocorrelation usually make the true uncertainty larger, so t here is, if anything, generous.

2 · The best-of-N bar

The entry at the top of a board was not chosen in advance; it is the best of N. If every entry were pure noise, the best of N would still look good. We raise the bar with a one-sided Bonferroni correction:

α = 1 − Φ(2) the one-sided rate implied by t = 2 (about 2.3%) bar(N) = Φ⁻¹(1 − α / N)

Bonferroni assumes the entries are independent attempts. When they are correlated (parameter variants from one owner, teams using the same model), it overcharges. We say so on every edition rather than switch to a correction whose assumptions a reader cannot check.

3 · The earliest date a winner could be shown

A result of "nobody is significant" says little on its own. So we turn it into a date: how many months of clean, forward history would the top entry need to clear the bar, if its true Sharpe were S?

months = (bar(N) / S)² × 12

We report it at S = 5 and S = 2, and at the closest entry's observed Sharpe. These are conditional statements, not forecasts: no one knows any entry's true Sharpe, and a high observed Sharpe on a few weeks of data is itself mostly noise.

What this does not do

  • It does not say any entry is unskilled. It says the board's data cannot yet tell skill from luck.
  • It does not check whether the model had already seen the test period. Live boards are closed-book by construction; for backtests, see the cutoff audit.
  • It uses only what the board publishes. Where an entry publishes no history, we say so and compute nothing.
  • It applies the same rule to every board. No board is graded on a curve.

Reproduce it

pip install evidence-deflator python tools/build_leaderboard.py --la DIR --aitrader FILE --out 2026-10.json

Raw responses for every edition are kept and available on request. If you operate a board and think a number is wrong, open an issue; corrections are published in the next edition.

Related: Bailey & López de Prado, "The Deflated Sharpe Ratio" (2014); Lo, "The Statistics of Sharpe Ratios" (2002); Zhang & Stadie, "Temporal Leakage in LLM Backtesting" (arXiv 2608.02985).
